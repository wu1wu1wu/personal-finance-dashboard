# 个人记账看板

一个纯本地的个人记账应用：从微信支付账单和支付通知中采集交易，自动分类、统计、做预算。没有后端、没有账号，数据全部保存在你自己的设备上。

既可以当网页用，也可以打包成安卓 App 装到手机上。

## 功能

### 记账

- **账单导入**：支持微信支付与支付宝导出的 CSV / XLSX 账单，自动识别是哪一家、自动识别 GBK / UTF-8 编码，按交易单号去重，重复导入不会产生重复记录。支付宝的「交易关闭 / 等待付款」这类钱没动的记录不会入账
- **自动记账（安卓）**：读取银行短信与微信 / 支付宝的支付通知，自动生成交易记录
- **账单回填**：自动捕获的记录只有金额和时间（微信通知不带商户名），导入账单后会自动按「金额 + 时间」把商户、商品、真实交易单号补全，并重新分类
- **手动补录**：个别遗漏的交易可以手动添加

### 分类

- 10 个分类：餐饮美食、交通出行、购物消费、休闲娱乐、居住生活、医疗健康、教育学习、转账、其他、待确认
- 内置关键词规则，可叠加自定义规则（自定义优先级更高）
- **反馈学习**：手动修改分类会累积反馈，同一关键词达到 3 次自动升级为规则
- **习惯学习**：从历史账单学习「金额分档 + 时段 → 分类」，置信度足够高时才给出分类，并明确标注为「推测」
- **转账类**（转账 / 红包 / 提现 / 退款）单独归类，不计入支出统计与分类饼图

### 查看

- **看板**：KPI 指标、月度收支趋势、分类占比、每日支出、周期性交易识别、周期扣款提醒
- **明细**：按分类 / 月份 / 收支方向 / 金额区间筛选，按时间或金额排序，支持关键词搜索与滚动分页；点任意一行看详情，可**编辑金额、时间、交易对方、商品说明**，或直接删除。超过 60 条时列表自动虚拟化，上万条也不卡
- **月度报告**：单月一页看完——收支与环比、本月要点（自动生成的文字结论，可一键复制）、分类 TOP5、每日支出、最大一笔、周期扣款、待确认与预算执行；支持上/下月切换与 `?month=yyyy-MM` 深链
- **周期扣款提醒**：识别出的订阅会告诉你「几天后要扣」「该扣的没扣（可能已取消）」「涨价了没有」，并在看板上合计出**每月固定支出**；不想看的商户可以单独关掉提醒
- **待确认收件箱**：自动捕获但未能分类的记录集中在此，一键归类

### 预算

- 分类预算与总预算，按月份独立设置（含下个月，可以提前规划）
- 执行率到达 80% 黄色预警、100% 红色超支

### 数据

- 全部本地存储，无后端、无账号、不联网上传
- 一键导出 / 恢复 JSON 备份：导出分**脱敏版**与**完整版**
- 恢复前自动给当前数据存一份快照（保留最近 3 份），恢复失败自动回滚
- **删除可撤销**：删单笔或按月清理后，底部会留一条「撤销」；设置 → 数据管理里有「最近删除」，保留 30 天（最多 20 批、500 笔），封面图一并保留
- 一键清空所有数据（含最近删除与安卓端残留的通知/短信队列，清空后不会"复活"）
- 脱敏：银行卡号、手机号、交易单号自动打码，可在「设置 → 数据管理」里关闭
- 存储写失败会在页面顶部常驻告警，避免"以为保存了其实没有"

### 安装与离线

- **装到桌面**：浏览器里可以直接「添加到主屏幕」，装好后像原生 App 一样全屏打开
- **离线可用**：把应用装下来之后断网也能打开、记账、查账（数据本来就在本机）；页面请求走网络优先，资源按内容 hash 长期缓存
- 发新版会在页面底部提示「发现新版本」，点一下即可刷新接管；`sw.js` 与 manifest 不会被长缓存
- 安卓 App 里不会注册 Service Worker（WebView 本来就离线可用）

### 外观

- **深色模式**：跟随系统 / 强制浅色 / 强制深色三选一（设置 → 外观），切换即时生效
- **界面语言**：简体中文 / English 中英双语，连同图表文案与读屏文案一起切换（设置 → 外观 → 语言）；分类名等历史数据不受影响
- 两套配色的文字对比度都按 WCAG AA 校过，由单测守住；图表配色跟随同一套令牌
  
## 技术栈

| 层 | 选型 |
|---|---|
| 前端 | React 19 + TypeScript 6（strict）+ Vite 8 |
| 状态 | Zustand 5（手动持久化） |
| 样式 | Tailwind CSS 4 |
| 图表 | ECharts 6 |
| 路由 | react-router-dom v7 |

| 离线 | 手写 Service Worker（`src/pwa/sw.ts` → 构建为 `dist/sw.js`）+ Web App Manifest |
| 测试 | Vitest 4（541 个单测） |
| 代码检查 | oxlint |
| 移动端 | Capacitor 8 + @capacitor/preferences |

没有第三方 UI 组件库，所有界面元素均用 Tailwind 手写。

## 快速开始

```bash
npm install
npm run dev      # 开发服务器，端口 3000
npm run build    # 类型检查 + 生产构建，输出到 dist/
npm run test     # 运行单元测试
npm run lint     # 代码检查
```

## 打包安卓 App

需要 **JDK 21**（Capacitor 8 要求，17 不行）与 Android SDK。

```bash
npm run build
npx cap sync android
cd android && ./gradlew assembleDebug    # Windows Git Bash 用 sh gradlew
```

产物在 `android/app/build/outputs/apk/debug/app-debug.apk`，传到手机安装即可。

首次构建会联网下载 Gradle 与依赖，耗时较长。国内网络可在 `android/gradle/wrapper/gradle-wrapper.properties` 中把 Gradle 源换成腾讯云镜像，并用 `~/.gradle/init.d/` 配置阿里云 Maven 镜像。

## 数据存放

数据键名统一以 `pfd_` 开头：

| 环境 | 存储方式 |
|---|---|
| 网页 | `localStorage` |
| 安卓 App | Capacitor `Preferences`（底层 SharedPreferences） |

存储层通过 `StorageAdapter` 抽象，接口为 `get` / `set` / `remove` / `clear` / `keys`，未来可替换为 SQLite 或其他实现。

## 使用中可能遇到的问题

### 1. 微信支付通知里没有商户名，这是微信的设计

微信支付通知的内容只有「微信支付 / 已支付 ¥23.00」，商户名、商品、订单号都不在通知里。这不是读取失败，是数据本身不存在，任何 App 都拿不到。

所以自动捕获的记录只有金额、时间和收支方向，需要靠两种方式补全：

- **导入微信账单**：账单里带真实商户、商品和交易单号，导入时会自动按「金额 + 时间」回填到对应记录并重新分类。导出路径：微信 → 我 → 服务 → 钱包 → 账单 → 右上角常见问题 → 下载账单 → 用于个人对账。
- **待确认收件箱**：账单导出之前，未分类的记录会集中在这里，点开一键归类即可。

导出频率随意，一个月一次甚至更久都可以，回填不依赖导出频率。

### 2. 自动记账在国产系统上需要额外设置

- 必须手动开启「通知使用权」（在系统设置里开，App 无法代开）
- 建议把 App 的省电策略设为「不限制」并允许自启动，否则系统会杀掉通知监听服务
- App 保持通知监听连接时会实时收到每条通知，其他通知不会挤掉支付通知，也不要求支付通知一直停留在通知栏
- 自动记账交易时间使用通知的系统投递时间；短信使用短信自身时间，不依赖 App 何时打开
- 监听服务未运行时，只有在通知**还留在通知栏**的情况下，打开 App 才能补扫到；已经被划掉或点开过的通知无法找回
- 原生层会先过滤待支付、验证码、媒体播放等非交易消息，只把疑似已完成交易送入持久队列
- 短信通道需要短信权限，且不同银行的短信格式差异很大，可能识别不准

### 3. 分类可能不准

关键词规则只覆盖常见商户，新商户会落到「待确认」；习惯学习的推测分类也可能猜错（因此带「推测」标记）。

两种修正方式：在明细里直接改分类（会进入反馈学习），或在「设置 → 分类规则」里自己加关键词。

### 4. 账单回填可能配错商户名

回填规则是：金额完全一致 + 收支方向一致 + 时间差在 24 小时内，并且按时间最接近的一对一配对。

如果同一天有多笔金额完全相同的交易，理论上可能张冠李戴，把商户名配到另一笔上。**金额和收支方向不会出错**，只有商户名和分类可能受影响。发现配错时在明细里改一下分类即可。

### 5. 支付宝账单要先把压缩包解开

支付宝「开具交易流水证明」给的是一个压缩包，里面才是 CSV。本应用不直接读 zip，**请先解压，再导入里面的 CSV**。

微信账单导出的是 CSV 或 XLSX，可以直接导入。两家账单都会自动识别，不需要手动选择来源；重复导入不会重复记账。

**支付宝账单里「交易关闭 / 等待付款」的记录不会入账**（钱没动），导入结果里会告诉你跳过了几笔。

### 6. 存储容量与数据安全

- 交易封面图以 base64 形式存在本地，图片较多时会明显占用存储空间
- 网页版的 `localStorage` 可能被浏览器清理；App 版更稳，但「清除应用数据」同样会清空
- 建议定期用「设置 → 数据管理 → 导出备份」保存一份 JSON 到别处

### 7. 数据不会跨设备同步

纯本地设计，没有账号体系，换手机或重装需要手动导出 / 恢复备份。

### 8. 安装包是调试签名

仓库构建出的 APK 使用自动生成的调试签名，仅供自己安装使用。若要上架应用商店，需要另外配置正式签名。

### 9. 首屏体积

页面按路由懒加载、ECharts 按需注册、xlsx 改为动态导入后，首屏（入口 + 图表 + 看板）约 **1086 KB（gzip 后约 360 KB）**，明细 / 预算 / 设置 / 报告页不加载图表代码，Excel 解析（425 KB）只在真的导入 `.xlsx` 时才下载。

> 第三批改造前是单个 2.03 MB 的 chunk（gzip 约 666 KB），任何页面都要先下完 ECharts 和 xlsx。
> 第五批加入中英双语文案、报告与周期提醒引擎后，首屏比之前多了约 34 KB（gzip），约 +10%；
> 想找回这部分，可以改成只打包当前语言的文案（代价见 [docs/plan-batch5.md](docs/plan-batch5.md) 的验证记录）。

## 无障碍与配色约定

- 颜色令牌（`src/index.css` 的 `@theme`）必须满足 WCAG AA：正文 ≥4.5:1，白底与 canvas 底都要满足；由 `src/utils/contrast.test.ts` 与 `src/constants/chart-colors.test.ts` 守住，改浅了测试会失败。
- 图表配色单独放在 `src/constants/chart-colors.ts`（ECharts 读不到 CSS 变量），两处必须同值，测试会核对。
- 触控目标：仅图标按钮 ≥44×44 px；密集列表里的文字 chip ≥32 px 且相邻间距 ≥8 px（WCAG 2.2 目标尺寸的间距例外）。
- 图表都带 `role="img"` + 文字摘要；分类环形图的数据由旁边的 HTML 列表承载，图表本身对读屏软件隐藏。

## 国际化与文案约定

文案全部走 `src/i18n`，界面里不再有裸的中文字面量。改代码时注意：

- **中文是唯一事实来源**：`src/i18n/messages/zh-CN/` 下每个命名空间一个文件；英文那份标注 `Record<keyof typeof zhXxx, string>`，中文加了 key 却没补英文会**直接编译失败**。
- **命名空间不要互相串**：新增文案写进自己页面对应的那一份，别往别人的文件里塞（并行改动容易互相覆盖）。
- **占位符中英必须一致**：`{count}`、`{amount}` 这类参数由 `src/i18n/messages.test.ts` 逐 key 比对。
- **复数**用 `xxx_one` / `xxx_other` 变体，调用 `t('xxx', { count })`。
- **数据值不做翻译**：分类名、收支方向这类「数据里就有中文」的字段用 `categoryLabel()` / `transactionTypeLabel()` 映射；映射表用 `satisfies Record<CategoryName, MessageKey>` 保证漏一个就编译不过。
- **日期/月份**用 `formatDateForLocale()` / `formatDateTimeForLocale()` / `formatMonthForLocale()`（`Intl` 驱动），不要用写死中文的 `formatDateShort()`。
- **图表文案**由 `useChartLabels()` 注入到 option 构造器；坐标轴数值压缩用 `buildAxisFormatter(locale)`（中文按万、英文按 k）。
- 源码里 `t('...')` 的 key 必须真实存在——`messages.test.ts` 会扫描全部源码，拼错会失败；同时它还会检查命名空间之间没有重复 key。

## 项目结构

```
src/
  core/          # 纯逻辑引擎（无 React 依赖）
                 #   csv-parser        账单解析（微信 / 支付宝，xlsx 按需加载）
                 #   bill-format       账单格式识别与列名映射
                 #   classifier        关键词分类 + 反馈学习
                 #   habit-learner     习惯学习（金额 + 时段 → 分类）
                 #   transaction-reconcile  账单回填 + 重复导入保护
                 #   transaction-query 筛选 / 排序 / 汇总
                 #   transaction-filters 筛选条件 ↔ URL 参数
                 #   backup            备份校验 / 恢复回滚 / 快照
                 #   trash             最近删除（批次、TTL、上限）
                 #   dashboard-engine  看板统计
                 #   report-engine     月度报告汇总
                 #   recurring-reminder 周期扣款提醒
                 #   virtual-window    列表虚拟化的窗口计算
                 #   budget-engine     预算执行
                 #   periodic-engine   周期性交易识别（按商户索引 + 引用缓存）
                 #   data-masker       数据脱敏
  stores/        # Zustand 状态管理（交易 / 分类规则 / 预算 / 读取规则 / 设置 / 周期提醒忽略名单）
  components/    # 展示组件，按功能分组
                 #   charts/           ECharts 按需注册与统一封装
                 #   report/           月度报告要点生成
  pages/         # 顶层路由页面（全部按路由懒加载）
  i18n/          # 中英双语文案与翻译器（messages/ 下每命名空间一个文件）
  pwa/           # Service Worker（构建为 dist/sw.js）、缓存策略、注册与状态
  types/         # 类型定义与常量
  utils/         # 日期、格式化、ID 生成、文件下载、对比度等工具
  storage/       # 存储抽象层 + 持久化队列 + 封面图独立存储
  hooks/         # 自动记账 Hook、列表虚拟化 Hook
  plugins/       # Capacitor 原生插件封装
android/         # Capacitor 安卓工程（含自动记账的原生 Java 实现）
docs/            # 设计文档
public/          # favicon、PWA manifest 与图标
```

## 已知限制

- **支付宝账单需要先解压**：官方导出的是 zip，本应用只读里面的 CSV
- **支付宝通知解析仍未经充分验证**：账单导入是可靠的，自动记账里支付宝通知的识别准确率取决于通知样式
- 通知监听依赖系统授权与省电策略，不同 ROM 表现差异较大
- 自动记账的原生链路目前只在部分机型上验证过
- 全自动获取商户名需要无障碍服务读取账单详情页，涉及较高权限且易随微信改版失效，暂未实现
- **周期扣款提醒只做应用内提示**：不发系统通知（浏览器通知需授权且只在页面打开时有效，安卓本地通知要引新依赖）
- **同一商户的两个不同金额订阅会共用金额**：例如 Apple 的 iCloud 与 Music，两条提醒都会取该商户最新一笔的金额（识别按商户聚合，这样才检测得出涨价）
- **金额单位「元」不随界面语言变**：英文界面下金额仍显示为 `1,234.00元`（本应用只记人民币）
- **列表虚拟化的滚动/测量逻辑没有单测**：窗口数学是纯函数且有 14 条测试，但 `useVirtualList` 里的 ref/滚动/测量靠类型检查、构建与浏览器冒烟验证
- 应用的系统云备份已关闭（`allowBackup=false`）：交易库和短信/通知原文不会随云备份或换机迁移离开设备，跨设备请用「导出备份」
- 短信通道只申请 `RECEIVE_SMS`，不读取历史短信
- **账单主题功能尚未完成**：当前只支持给单笔交易填写文字主题或配置封面图；完整主题商店、皮肤切换、按主题批量管理等能力仍在规划中
