## 1. 手记是什么

一笔账单上的**一句话 + 一张图**（都可以没有，但至少有一个才算一条手记）。

- 文字上限 **80 字**（原来是 40 字，"手记"这个名字下 40 字写不完整句话）
- 配图沿用原来的压缩管线（`compressImage`：最长边 300px、JPEG 0.7），单独存 `pfd_cover_<id>`
- 看板右上角切到「手记」视图 → 当月有话或有图的账单**按大卡片铺开**（手机一列、`sm` 两列）

**存储字段名沿用旧的 `theme` / `setTheme`**：改名要写数据迁移、要动备份兼容，风险大收益小。类型定义与 store 上都注明了「theme = 手记文字」，界面文案一律叫手记。

## 2. 卡片交互

```
浏览态                                   编辑态（同一张卡片原地变形）
┌──────────────────────────────┐        ┌──────────────────────────────────┐
│ ⬤ ¥38    手记文字…         ✕ │        │ ⬤ [手记输入框（80 字，自动聚焦）] │
│          对方 / 说明          │        │    对方 / 说明                     │
│ 餐饮美食 · 9月30日 21:15      │        │ [加图/换图][删图]  [保存][取消]    │
└──────────────────────────────┘        └──────────────────────────────────┘
```

- **点卡片空白** → 进该笔详情（`/transactions?id=`）
- **点手记文字** → 进入编辑态（没有单独放铅笔按钮，是按用户意见省掉的）
- **✕** → 移出手记：文字与配图一起清，卡片立刻消失；屏幕下方留一条 **8 秒撤销**
- **编辑态里不出现 ✕**，避免正在改字时手滑把整条删了
- 手记被改成空、且没有配图时，卡片也会消失，同样给一条撤销（`手记已清空`）
- 「取消」按钮在 `pointerdown` 上 `preventDefault`：否则失焦保存会抢在取消之前把内容写进去

结构上把「整个卡片套一个 `<button>`」拆了：那种结构里放不了输入框。改成一张铺满卡片的透明按钮负责进详情、内容层压在它上面——与明细列表行同一套写法。

## 3. 口径收口（这次 bug 的根因）

原来「这笔算不算手记」的判断（`theme || coverImage`）散在页面里，而 ✕ 只清 `theme`，两边口径对不上，于是带图卡片永远删不掉。现在统一到 `src/core/transaction-note.ts`：

- `hasNoteCard(txn)`：卡片是否陈列的唯一判断（纯空白文字不算）
- `normalizeNote(raw)`：去首尾空白 + 按 80 截断；**store 的 `setTheme` 入口也统一清洗一次**，卡片、详情弹窗、以后新增的入口都守同一条上限
- `clearedNotePatch()`：一次清空文字与配图

`clearNote(id)` 在**同一次 `set`** 里清掉两个字段（分两次写会对整个交易数组多序列化一遍，中间那一帧还会出现「文字没了、图还在」的半截状态），并顺手删掉 `pfd_cover_<id>`，不留孤儿数据。

## 5. 取舍

- **保留大卡片**：不改成明细式行，也不动底部导航（用户后续再定）。
- **不做卡片样式/皮肤模板**：README「已知限制」里那条已从"主题商店/皮肤切换"改写为"手记没有样式模板"，明确留给后续。
- **没有铅笔按钮**：用户明确不要，编辑入口只有"点手记文字"。
- **撤销只活 8 秒、只在当前页面内存里**：它不是回收站条目（交易本身没被删），刷新页面就没了；好处是不用为它加一份持久化结构。
- **副标题不再重复标题**：没有手记时标题就是交易对方，原来副标题会把同一句话再显示一遍；现在只有同时存在对方与商品说明时才补一行。
- **手记最长 3 行**：80 字在卡片上最多三行，再长也会盖掉配图的渐变。

## 6. 已知缺口

- 卡片的交互（点击分区、编辑态、撤销）**没有单测**：项目单测是 node 环境、无 jsdom，只有纯逻辑（`transaction-note`、store）进得了测试；这部分靠 `tsc` + `oxlint` + 构建 + 浏览器手测。
- 配图仍是 base64 存在本地，图片多了占用可观（原有已知限制，未变）。
